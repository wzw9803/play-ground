# 专利技术交底书答疑工作流

## 适用场景
用户提供专利技术交底书(通常为加密 docx),内含专利工程师的提问(常见形式:"Q1，待确认：…"、"Q2，…"、"待确认：7.1.X中哪些步骤存在核心改进？…"等,通常以 Word 修订 `w:ins` 形式插入,作者为专利工程师)。需要:

1. 逐问回复(直接可答的答;需发明人拍板的用 AskUserQuestion 问)
2. 把定稿答复回填进交底书(普通文本版 + Word 修订版)

## 最高约束(发明人明确要求,不可违背)

1. 只基于交底书原文 + 公开行业规范(如 3D Tiles、CesiumJS、Three.js、WebGL、MDN)分析;使用查询工具时标记来源与可靠性
2. 严禁杜撰、脑补、合理化推测不存在的技术事实;缺失内容用【事实缺失】占位或向发明人提问
3. 推断性内容必须标注"此为推断";需发明人确认的标 needs-clarification
4. 不引入发明人技术背景之外的方案(本用户背景:计算机图形学、AI、WebGL/WebGPU、GIS、3D 引擎开发)
5. 不允许为了"看起来完整"而牺牲真实性

## 流程

### 阶段 1:解密与提取
1. 加密检测:`file 目标.docx`——若输出 `CDFV2 Encrypted` 则为 OLE 加密文档(非真 docx zip)
2. 解密:临时 venv 安装 `msoffcrypto-tool`;`OfficeFile.load_key(password=…); decrypt()`;**向发明人询问密码**
3. 提取文本:`textutil -convert txt -stdout <解密文件>`(textutil 能提取 `w:ins` 修订内的文本)
4. 结构探测:python-docx 检查 body 子元素——内容常在**表格/嵌套表格**中;用 `doc.element.body.iter(qn('w:p'))` 递归收集所有段落
5. **关键**:专利工程师的问题文本在 `w:ins` 修订里,`paragraph.text` 提取不到!需自定义提取器合并所有 `w:t`(含修订内)+ `m:t`(OMML 公式)

### 阶段 2:问题梳理
- 找出所有 "Q1/Q2/…/待确认" 段落,按章节分组编号(总述、7.1.1、7.1.2…)
- 注意:同一段落可能含多个问题;全角/半角冒号混用;问题与公式间常有 "```" 代码块标记段

### 阶段 3:多 agent 分析回答(Workflow)
- 按章节分组并行分析 + 1 个汇总 agent 写答复文档
- 每个 agent 输出结构化:question / answer / answerType / source / reliability
- answerType 枚举:based-on-document(文档依据)/ based-on-public-spec(公开规范依据,给出处)/ inferred(推断,标"此为推断")/ needs-clarification(需发明人澄清)
- 汇总 agent 必须**核对问题覆盖数**(防止漏答;历史教训:某组 12 问只答了 3 问)

### 阶段 4:发明人澄清(AskUserQuestion)
- 文档无法推断的关键事实(场景形态、术语定义、场景来源、参数语义、方案冲突)用 AskUserQuestion 选项式提问(每次最多 4 问)
- 把澄清结果记录到 `发明人澄清记录.md` 留档

### 阶段 5:待澄清问题起草(给选项让发明人勾选)
- 实现细节(参数取值、计算方式、流程顺序)以【建议方案 A/B/C】形式呈现,供发明人勾选——**不把建议写成既定事实**
- 检查跨组自洽性(K 值、优先级语义等在 7.1.1 与 7.2 等章节间必须一致),不一致列出

### 阶段 6:合并定稿
- 把发明人确认的方案合并进答复文档,消除"需要发明人澄清"等未决表述
- **发现矛盾(如两处对同一参数选择不同)必须用 AskUserQuestion 问,不擅自决定**

### 阶段 7:检验(多 agent)
- 逐问检验:切题性 / 完整性(子问题逐一核对)/ 明确性(无未决表述)/ 事实性(与公开规范一致)/ 交付性(专利工程师无需再追问)
- 判定 pass / partial / fail,汇总报告
- **复核检验 agent 的数学计算**(历史教训:检验 agent 给出过错误算例,F_fog 计算错误)
- partial/fail 修复后重跑检验或人工复核

### 阶段 8:回填 docx
- 用 `scripts/fill_docx.py` 模板(参数化路径,映射表按当前交底书问题原文调整)
- 生成两个版本:普通文本版 + `--revision` 修订版(`w:ins`,author=发明人姓名,与专利工程师插入问题的方式一致)
- 验证:`textutil` 提取检查【答复】数量;unzip 检查 `w:author="发明人"` 的 w:ins 数量

## 关键陷阱速查

| 陷阱 | 解法 |
|---|---|
| 文档是 CDFV2 加密 OLE 而非 docx | msoffcrypto-tool 解密 |
| 问题文本在 w:ins 修订里 | 自定义提取器合并 w:t(含修订内) |
| 公式文本在 m:t(OMML) | 提取器同时收集 m:t |
| 内容在表格/嵌套表格 | body.iter(qn('w:p')) 递归收集 |
| "```" 代码块段隔断公式与问题 | 上下文回溯判断时跳过 ` ``` ` 段 |
| 同一段落多个问题 | 支持一段插入多个答复 |
| 全角/半角冒号混用 | 关键词避开标点或用稳定子串 |
| 检验/汇总 agent 漏问题或算错数 | 核对覆盖数 + 人工复核数学 |
| 合并时发现方案矛盾 | AskUserQuestion 问发明人,不擅自决定 |
